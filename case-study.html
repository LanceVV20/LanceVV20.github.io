SauceDemo: end-to-end QA of an eCommerce checkout

A full QA cycle on SauceDemo, a public demo store built for testers. It covers the plan, the test cases, the defects, and the report, with every case and bug reproduced by an automated Playwright test.

01

Test plan

Objective

Verify that a shopper can log in, browse products, manage a cart, and complete checkout correctly, and find defects that would block or degrade a purchase.

In scope

  • Login and session handling
  • Product listing and sorting
  • Cart add, remove, and persistence
  • Checkout form, validation, totals, and confirmation

Out of scope

  • Payment processing (demo app, none exists)
  • Backend and API (no public API)
  • Load testing
  • Footer and social links

Approach

  • Requirement-based functional tests
  • Negative and validation tests
  • Exploratory sessions per test account
  • Automated regression with Playwright and the Page Object Model

Test accounts

  • standard_user baseline
  • locked_out_user access
  • problem_user UI defects
  • performance_glitch_user speed
  • error_user errors

Entry / exit criteria

Entry: app reachable, test accounts available.

Exit: all planned cases executed, every defect logged with repro steps, and no open Blocker on the baseline user.

Risks

Verdict & recommendations

standard_user: ready. All 21 cases pass, including the full purchase flow and total calculation.

Not ready to release for the conditions represented by problem_user and error_user: two Critical defects and one Blocker prevent a customer from completing an order.

  • Fix BUG-006 and BUG-004 first: both block revenue.
  • Add server-side validation for required checkout fields (BUG-007) instead of relying on the UI alone.
  • Set a login performance budget (≤ 3s) and monitor it in CI (BUG-005).
  • Keep the test.fail() checks so each fix is verified automatically and nothing regresses.
